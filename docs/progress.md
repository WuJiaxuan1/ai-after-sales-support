# 开发过程记录

以下按开发阶段整理行动、发现的问题与处理结果。阶段顺序依据已有过程文档整理；仓库上传时间代表本次公开整理时间。

## 问题定义与方案选择

- 明确售后用户、人工客服和平台运营方的目标，以及知识、权限和安全边界。
- 比较纯模型对话、规则分类和混合流程，确定 Workflow、受限 AI、RAG 与人工交接的组合。
- 明确模型输出与真实业务动作的区别，以 Case、Queue 和 Audit 作为状态核验依据。

## 初始 MVP 与联调

- 实现 Workflow、Case 管理、RAG、模型适配器、交接、优先级和 API。
- 联调用户端与客服端，处理模型响应为空、接口兼容、延迟和中文检索问题。
- 建立初期回归测试，将接口不一致与失败样例作为后续修正输入。

## 流程与检索重构

- 将自由文本限制在当前节点的映射扩展为既有流程中的最长可靠候选路径。
- 增加路径合法性校验和用户确认，避免模型判断直接写入正式业务状态。
- 调整普通咨询的检索时机，使知识问答不依赖完整的业务分类。

## 安全与人工交接

- 将全局安全判断、Workflow、RAG 和人工接管组织到统一服务层。
- 修复模型文本宣称建单而客服队列没有真实工单的问题。
- 对明确和疑似安全风险创建真实 P0 交接，并保留风险类型、依据和用户原话。
- 验证主动找人工、能力不足、权限边界和自动处理无进展等交接场景。

## 状态与优先级核验

- 核对 P0–P3 优先级与队列顺序，避免用户自报金额直接成为已核验经济暴露。
- 限制客服接单、回复和解决的状态顺序，检查真实 Case 和审计记录。
- 区分真实模型结果与确定性 fallback，避免把页面显示正确等同于模型验证通过。

## 最终修复与公开整理

- 修复退货规则咨询被历史上下文误判转人工的问题。
- 修复客服回答暴露内部知识库措辞的问题。
- 整理规则、实现、维护和测试说明，保留现有边界回归样例。
- 移除公开副本中的硬编码模型密钥，改为环境变量配置。
- 统一网页标题，补充运行命令、依赖和公开版项目文档。
