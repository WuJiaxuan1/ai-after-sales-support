# 测试与验证

## 自动化回归

测试位于 `src/tests/test_ai_judgment.py`。安装根目录 `requirements-dev.txt` 后，在 `src` 目录执行 `python -m pytest tests -q`。

| 测试场景 | 检查的结果 |
| --- | --- |
| “我的充电宝爆了” | 创建真实 P0 人工交接，并保存风险类型与用户原话 |
| “我的充电宝有点热” | 疑似风险同样进入 P0 人工队列 |
| “没有冒烟，只是开不了机” | 否定语境不误触发规则安全 Gate |
| “找真人” | Case 真正进入客服队列 |
| “你给我仅退款吧” | 识别业务执行权限边界并交接人工 |
| 仅描述鼠标故障 | 不自动创建退款意图 |
| 合法与伪造候选路径 | 只接受既有流程中的连续合法路径 |

这些测试不调用真实模型。原项目验证记录报告了 7 项通过；这是历史记录，公开整理与重新执行回归属于不同步骤。

## 人工端到端验证

同时打开 `/user` 和 `/agent`。分别检查普通规则咨询、安全场景和主动找人工；在客服端检查队列、P0 标记、交接原因、用户关键原话和对话历史。接单并回复后，再检查能否完成解决状态。

判断业务动作时查看实际 Case、Queue、Handoff Packet 与 Audit。模型回复“正在转人工”不能替代真实队列记录。

## 验证边界

未设置密钥时运行的是规则与降级路径。需要验证真实模型时，使用自己的环境变量配置，并检查 Audit 中的模型调用与降级记录。规则测试通过不等于已验证模型对全部长尾表达的表现。
